# Authlete API ロードテスト結果 (2025-10-08)

- 使用スクリプト: `scripts/load_test_authlete.py`
- 環境変数: `.env` の `ORGANIZATION_ACCESS_TOKEN`, `ORGANIZATION_ID`, `AUTHLETE_API_URL` を使用
- テスト条件:
  - リクエストレート: 約 100 RPS
  - 実行時間: 5 秒
  - 対象エンドポイント: `/api/service/get/list?limited=true&start=0&end=1`
  - 総リクエスト数: 500

## サマリー

| 指標 | 値 |
|------|----|
| 成功レスポンス (HTTP 200) | 247 |
| レートリミット応答 (HTTP 429) | 253 |
| 最小レイテンシ | 約 48.89 ms |
| 最大レイテンシ | 約 1836.79 ms |
| 平均レイテンシ | 約 410.16 ms |

## 観測内容

- HTTP 429 (Too Many Requests) が 253 件発生し、GitHub Actions で観測されたエラーと同種のレートリミット応答を再現できた。
- 応答本文には nginx からのレートリミットページが含まれており、Authlete 側のゲートウェイでレート制限がかかっていることが確認できる。
- 100 RPS を継続すると、約 0.4 秒平均、最大で 1.8 秒程度の応答遅延が発生し始める。

## 次の検討事項

1. CI や長時間バッチ処理では、リクエストレートを 50 RPS 未満に抑える、または指数バックオフ付きの再試行を導入するなど、負荷制御が必要。
2. `Retry-After` ヘッダーなど追加情報の取得をスクリプトに実装し、動的に待機時間を調整できるようにする。
3. 必要に応じて Authlete 側のレートリミット引き上げを相談する。
